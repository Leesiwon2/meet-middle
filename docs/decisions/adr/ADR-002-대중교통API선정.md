# ADR-002: 대중교통 소요시간 API 선정

> 상태: **Proposed** · 작성일: 2026-11-11 · 결정일: (P0-21 PoC 후)
> 관련: [DESIGN.md](../../prd/DESIGN.md) §5·§6, [PHASE-0](../../plan/PHASE-0-기초작업.md) P0-21
> 범위: `external/transit` 어댑터의 기본 구현. 인터페이스(`TransitClient`)는 이 결정과 무관하게 고정.

## 1. 맥락

추천 알고리즘은 "출발지 → 후보 역" 대중교통 소요시간 행렬이 핵심 입력이다. 계산 1회에 최대 360 호출(10명 × 12후보 × 3시나리오, DESIGN §5.6. 시나리오 간 캐시 공유로 실제는 더 적음). 카카오·네이버는 대중교통 길찾기 공개 API 가 없다.

## 2. 기준

1. 정확도: 실제 앱(카카오맵/네이버지도) 소요시간과의 차이
2. 비용·한도: 무료 일일 한도, 유료 단가, 상업적 이용 허용 여부
3. 안정성: 응답 시간 p95, 실패율
4. 응답 정보: 소요시간, 환승 횟수, 도보 시간 제공 여부
5. 약관: 결과 캐싱(7일) 허용 여부

## 3. 선택지

### A. ODsay LAB (잠정 1순위)
- 장점: 대중교통 전문, 국내 서비스 사용 사례 많음 [추정]
- 단점: 한도·요금 미확인

### B. TMAP 대중교통 API (SK open API)
- 장점: 대형 사업자, 경로 품질 [추정]
- 단점: 요금 체계 미확인

## 4. PoC 계획 (P0-21)

- 표본: 출발지 10곳(서울 동·서·남·북, 경기 남·북, 인천) × hub 10곳 = 100 경로, 평일 19시 기준
- 측정: 각 API 소요시간, 환승 수, 응답 ms, 실패 여부 + 같은 경로 카카오맵 앱 수동 확인 10건
